## Changes

All four files are under `uw-genie-infra/src/notebooks/`. The three notebooks use Databricks source format, so bundle sync uploads them as notebooks. `uw_seed.py` is a plain Python module.

* `uw_seed.py` (new, shared module): deterministic book generation in plain pandas/numpy, with seed 2027 and no Spark. It holds every pinned L300-01 value: Northwind; assumption set AV-2027.1 (completion factors, trend, pooling, Northwind manual factors, retention, tier factors); the persistency curve; Northwind plan options; the 14-item intake checklist (7 BLOCKING, 7 WARNING); the trend_monitor rows; and the 25-row `broker_submissions` seed. It reads Northwind census v1+v2, claims (v2 incurred file) and large claimants v1+v2 from `docs/demo-assets/broker_packages`. It generates Lakeview and 58 random in-force groups. `package_gaps()` checks a broker package against the 5 L300-05 blocking gaps.
* `generate_synthetic_book.py`: cells 1–2 are `%pip install --upgrade databricks-sdk` and `dbutils.library.restartPython()`. Widgets are `catalog`, `schema` and `assets_dir` (optional override), and identifiers are validated. The notebook overwrites the rows of the 16 loaded tables with `insertInto(overwrite=True)`. It then runs about 30 assertions and fails the task if any fails.
* `upload_packages.py`: same first cells and widgets. It copies `northwind_v1` and `northwind_v2` to `/Volumes/<catalog>/<schema>/broker_packages/<pkg>/`, overwriting files and removing stale ones. Then it checks the copies in the volume: v1 has exactly the 5 seeded gaps, v2 has none, file sizes match the source, and every email uses `.example`.
* `reset_demo.py`: same first cells, widgets `catalog`/`schema`. This restores the statuses and drops any submission added during the demo. It then verifies the result. Scenario rebuild and tests are not in the notebook: the `reset_demo` job runs them next as SQL tasks (`10_`, `90_`), as session 01 asked.

## Data decisions

* **claims_monthly grain:** one row per group × incurred month, `service_category = 'ALL'` (medical + Rx). L300-01 pins Northwind at 24 rows of 436,666.67 each, so a MEDICAL/RX split would break the pinned values. The DDL comment says `MEDICAL|RX`, so the comment should change (request to 06). The broker files keep the medical/Rx split (24% Rx).
* **Northwind paid total:** 24 × 436,666.67 = 10,480,000.08, the same as the broker file. The assertion compares at whole dollars. The golden CSV results do not change.
* **Northwind v1 data:** kept with `census_version='v1'` (22 employee rows with null DOB or tier) and `package_version='v1'` (3 claimants with status `UNKNOWN`). The v1 paid-basis claims file is **not** loaded into `claims_monthly`, because `rate_new_business` sums every claims row for the group.
* **Lakeview (GRP-LV-002):** 1,390 EEs and 3,200 members (76,800 MM); current premium 548.00 PMPM; renewal 2027-01-01; claimants LC-01 Cardiac surgery RESOLVED 545K and LC-02 Oncology ACTIVE 390K; one `current` plan (Choice PPO 1500, relativity 1.00); manual factors 505 / 1.00 / 0.99 / 1.05. The completed claims PMPM (426.00) was tuned so that the L300-02 method gives +9.37% at $250K/base. That is consistent with its pipeline `recommended_rate_action` of 0.094 (and +11.6% at $150K).
* **plan_designs:** every in-force group (59) has a `current` row, so `rate_renewal` (session 03 uses plan_option 'current') works across the whole book, not only Lakeview. That makes 61 rows, against L200-01's approximate 12.
* **renewal_pipeline:** 59 rows (58 random + Lakeview), against L200-01's approximate 58. Renewals fall in Jan–Jun 2027 (31 in Q1, 28 in Q2). Rate action is N(0.085, 0.05) clipped to [−0.05, 0.30]. 6 groups have `new_large_claimant_flag` (Lakeview + 5 random). quote_due_date is renewal minus 60 days. Owners are "Underwriter A–D".
* **broker_submissions:** 25 rows. Northwind `SUB-NW-001-V1` is BLOCKED (top missing item "24 months of claims experience"). `SUB-NW-001-V2` is READY_WITH_WARNINGS ("Renewal offer from incumbent"). The other 23 are prospects `GRP-NB-101..123`; they are pipeline-only and not in `groups`, which keeps groups at 60. Final mix: 9 READY, 8 READY_WITH_WARNINGS, 8 BLOCKED.
* **Other tables:** completion_factors covers lags 0–36 (lags 2–7 pinned, all others 1.000). The persistency band edges are [min, max) with −1.00 / 10.00 at the open ends. trend_monitor has 3 rows; only Rx (13.4% vs 11.0%) is off by 1 point or more. submission_findings starts empty.
* Row counts: census_members 42,715 (≈42K), claims_monthly 1,440, large_claimants ≈150, groups 60.
