## Decisions
* **Metric view source is fully qualified via EXECUTE IMMEDIATE.** Metric view YAML cannot take parameter markers, and the docs say a table source uses a three-part name. Each metric view DDL is therefore a string template. Its `__FQ__` token is replaced with the backtick-quoted `catalog`.`schema` (backticks escaped) held in session variable `uw_fq`, and the result runs with `EXECUTE IMMEDIATE uw_sql`. The plain view uses unqualified names under `USE CATALOG/SCHEMA`, like `00_ddl.sql`.
* `source:` is a double-quoted YAML scalar, because a plain YAML scalar cannot start with a backtick. My static check caught this as a parse error, and it is fixed.
* SQL string literals inside the YAML (`'WEEK'`, `'v1'`, `'BLOCKED'`) are escaped as `\'` in the template, and the template text has no apostrophes.
* Measure names follow L300-03 (display names with spaces, e.g. `Projected Loss Ratio`, `Premium at Risk (Uncapped)`). The semantics docs' data-usage lines use snake_case (`mv_quote_outcomes.projected_loss_ratio`, `mv_renewal_book.premium_at_risk`). The manifest scope points to L300-03, so the L300-03 names win. Queries must backtick the names.
* `Target Loss Ratio` stays `ANY_VALUE(0.88)` as in the spec. Its comment says it is 1 - retention (12%).
