## Decisions and deviations

1. **Literal dev identifiers in the space file.** The plan asks for `${var.catalog}.${var.schema}.<table>` identifiers. The manifest scope requires `file_path`, and the bundle does not substitute variables inside a `file_path` space file. That fact comes from a comment in the agenticTrading bundle (`trade_analysis.genie.yml`), which moved to an inline `serialized_space` for this reason; I did not test it here. So the file uses `hls_fde_dev.uw_genie.*`. This works for dev. **Demo (`hls_fde`) needs a rendered `serialized_space` variable or a per-target file** (see requests).
2. **`file_path` is `../../underwriting_genie.geniespace.json`.** Bundle paths are relative to the YAML file, and the plan puts the JSON at the bundle root, so `./` from `resources/genie_spaces/` would not resolve.
3. **Dev root_path override.** I first used the shared `workspace.root_path: /Workspace/.bundle/${bundle.name}/${bundle.target}`. Validate then failed: `root_path must start with '~/' or contain the current username ... when using 'mode: development'`. The dev target now overrides it with `~/.bundle/${bundle.name}/${bundle.target}`, and demo keeps the shared path. Session 01's infra bundle will hit the same error.
4. **Creating the file.** `createAsset` and workspace import with `format: AUTO` both rejected `.geniespace.json` (`node type [UNKNOWN]`). The file was created through workspace import with `format: RAW`, then filled with editAsset.
